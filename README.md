# 3D Environment Scanner
### Purpose:
The purpose of this project is to design, build, and test a device to create 3D maps of indoor enviironments. The project would involve combining a microcontroller, time-of-flight (ToF) sensor, motor, and PC to run processing on the collected data.

### Specs and Limitations:
1. **PC Communication Speed:** The maximum standard UART baud rate that can be implemented for this project is 1,000,000 bps. This was determined through manual testing with setting different UART baud rate divisors in the microcontroller’s setup code. The UART clock of the microcontroller is driven by a 16MHz oscillator. During testing, it was found that UART signals were not received by transmission software when the integer baud rate divisor was zero, regardless of the value of the fractional baud rate divisor. Thus, according to the formula for calculating the baud rate of the microcontroller, the highest allowable speed is 1,000,000 bps as shown: $$\frac{16MHz}{16\times\left(\text{IBRD}+\frac{\text{FBRD}}{64}\right)}=\frac{16,000,000}{16\times\left(1+\frac{0}{64}\right)}=\frac{1,000,000}{1}= 1,000,000\text{ bps}$$
2. **ToF Communication Speed:** The microcontroller and time-of-flight sensor communicate via the I2C protocol at a rate of 100 kbps.
3. **Microcontroller Clock Speed:** The bus speed of the microcontroller is determined by the equation $$SYSCLK=\frac{\frac{f_\text{SRC}}{(Q+1)(N+1)}\times \text{MINT}}{\text{PSYSDIV+1}}$$ (there is another term, MFRAC, that is excluded from this calculation as it is set to 0 for best performance). Therefore, to achieve the target system clock of 36MHz using a 25MHz crystal oscillator, N was set to 4, Q was set to 0, MINT was set to 36, and PYSISDIV was set to 4. This yields $$\text{SYSCLK}=\frac{\frac{25,000,000}{(0+1)(4+1)}\times36}{4+1}=\frac{5,000,000\times36}{5}=36,000,000\text{ Hz}=36\text{ MHz}$$
4. **Sources of Error:** The scanner contains several small sources of error outside of the limitations of the system's sensors. First, rounding errors occur when converting the motor's position into an angle in radians, especially when multiplying by pi. Then, more errors would occur since there is a limit to the precision of the output of the trigonometric functions used on the resulting angle. Next, the result is multiplied by the distance measurement, amplifying any inaccuracies that accumulated from the previous steps. Finally, the data's accuracy will suffer from floating-point precision errors as a result of using a base-2 number system.
5. **Speed Limitation:** The primary limitation on system speed is the rotation of the motor. For every scanning cycle, the motor takes several seconds to rotate for the measurements and then repeats this process to unwind the wires. It’s rotation speed, 5ms per step with 2048 steps in a full rotation, is extremely slow in comparison with the 100Hz scanning speed of the time-of-flight sensor, the 100 kbps clock speed of the I2C communication, the 115,200 bps UART baud rate used between the microcontroller and PC, and the 36 MHz clock speed of the microcontroller. Since all data processing is performed on an external PC with a much higher clock speed, the 36MHz clock speed of the microcontroller is more than fast enough to keep the system running quickly. This leaves the motor’s rotation as the primary bottleneck since no processes can occur while this happens. The secondary bottleneck is the ToF scanning time. While, when the system is operating normally, the pauses it creates are almost imperceptible, when scans fail and multiple retries are required, the sensor causes visible delays in the motor’s rotation, creating a second speed bottleneck.
6. **Quantization Error:** The maximum quantization error of the ToF sensor is approximately 0.061. This was determined by taking the maximum measurement, 4000mm, and dividing it by two to the power of the number of bits used to store the measurement, in this case, 16. This yields $\text Q_{\text{ERROR}_\text{𝑚𝑎𝑥}} = \frac{4000}{2^{16}} \approx 0.06104$.

### System Usage:
After setting up the 3D Environment Scanner, run the `Hallway_Scan_App.py` file found in `./CODE/PC_application/` using Python 3.11. When prompted, indicate whether you are creating a new file “n”, appending to an existing file “a”, or simply reading data from a previous scan “r”. If appending to a file, you will need to indicate which portion of the scan you wish to append to. Scans are zero-indexed, meaning the first scan is scan 0. If the number of the last scan is unknown, the raw.csv file that is generated can be consulted, where the first column is the scan number. Similarly, the first column of the `.xyz` file can be consulted to determine the last scan number. In this case, divide the number in the first column by the value of the `SCAN_DISTANCE` variable (defaults to 300) to get the scan number. Once this value is entered, the steps for the “append” and “new” options are the same: press the start button (PJ0) on the device, let the motor spin a full circle, and then unwind. Once complete, either press start on the device again to take the next scan or press the terminate button (PJ1) to stop data collection and visualize the data. If, at any time, data collection needs to be paused (for example, a person needs to walk through the path of the sensor), press PJ0 to pause data collection and the motor’s rotation. When ready to continue, press PJ0 again to resume. No steps need to be taken on the side of the PC software.

### Results:
After using the 3D Environment Scanner, the data visualization process will begin automatically, first showing the scan as a 3D point cloud, and then showing it as a wireframe model. In both cases, the pop-up windows support click-and-drag controls to view the data from multiple angles in addition to pinch gestures to zoom in and out. After both visualization windows have been closed and the program shuts down, there will be two new files in the folder with the PC application. One will be a `.xyz` file containing the data points used for visualization, and the other will be a `.csv` file containing raw measurement data. If the `.xyz` file is lost, at the start of the next “read” or “append” operation involving this file, the `.csv` file will be used to regenerate the missing data.
